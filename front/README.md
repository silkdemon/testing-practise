# Форма — учебный магазин

Фронт по согласованному макету: React, TypeScript, Vite, React Router и MSW.
Это локальное учебное приложение без оплаты и доставки. Доступны настоящий API
на Go + PostgreSQL и автономная имитация MSW. Запуск бэка: [back/README.md](../back/README.md).

## Запуск

Нужен Node.js **22.12+**, рекомендуется Node.js 24 (версия указана в `.nvmrc`).

```sh
cd /Users/shevchukmary/testing-practise/front
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. На этом Mac Node.js 24 уже установлен в
`/usr/local/bin`, но оболочка может выбирать старый Node.js 20 из nvm. В таком
случае команды запускаются так: `PATH="/usr/local/bin:$PATH" npm run dev`.
Менять глобальные настройки Node.js не нужно.

```sh
npm test          # проверки правил API, корзины и оформления
npm run build    # TypeScript + production-сборка
npm run preview  # просмотр сборки на http://127.0.0.1:4173
```

MSW включён по умолчанию, в том числе в production-сборке учебной версии.
Service Worker запускается до первого запроса. Нужен localhost или HTTPS.
`file://` не поддерживается. Смена порта/имени хоста создаёт отдельное хранилище.

## Что работает

- `/catalog`: шесть товаров из макета, поиск, категории, сортировка. Параметры
  хранятся в URL и восстанавливаются после обновления страницы.
- `/products/:id`: карточка, характеристики, наличие, добавление в корзину.
- `/cart`: гостевая корзина, количества, удаление и итоговая сумма.
- `/login`, `/register`: проверка форм, неверного пароля, занятого email;
  автоматический вход после регистрации.
- `/checkout`: доступ после входа; возврат сюда после входа/регистрации;
  контактные данные, адрес и необязательный комментарий.
- `/orders/:id`: сохранённое подтверждение заказа. Обновление страницы не
  создаёт заказ повторно. Доступен только владельцу.
- Пустые состояния, загрузка, ошибки и страницы 404; адаптация к узким экранам;
  светлая/тёмная палитра следует системной теме.

Гостевая корзина переживает перезапуск браузера. При входе она объединяется
с корзиной аккаунта, с ограничением по остатку и уведомлением. Выход оставляет
корзину в аккаунте и показывает отдельную гостевую корзину. Заказ очищает
корзину только после успешного ответа. Черновик оформления хранится в
`sessionStorage` отдельно для каждого аккаунта и переживает повторный вход
при истечении сессии; явный выход очищает его.

## Учебная учётная запись

- Email: `demo@example.com`
- Пароль: `Demo12345`

Это публичные тестовые данные. Также можно зарегистрировать новый аккаунт.
В режиме MSW все данные остаются в локальном хранилище браузера: аккаунты,
хеши учебных паролей, корзины, сессии и заказы. В режиме настоящего API эти данные
хранятся в PostgreSQL, а браузер хранит токен сессии, гостевой ключ и черновик формы. Используйте вымышленные контакты и отдельные
учебные пароли. Клиентская имитация не является настоящей системой безопасности.

## Структура

```text
src/
  app/          # маршрутизация, общий каркас, пользователь и корзина
  api/          # HTTP-клиент, типы запросов и ответов
  components/   # поля, состояния страниц, иллюстрации товаров
  features/
    catalog/
    auth/
    cart/
    checkout/
  mocks/        # данные, имитация сервера и HTTP-обработчики MSW
  styles/
tests/          # проверки бизнес-сценариев имитации API
public/         # Service Worker MSW и favicon
```

Компоненты не импортируют хранилище или обработчики MSW. Иллюстрации товаров
перенесены из макета и выполнены средствами CSS; внешние изображения не нужны.

## Контракт API

Базовый путь `/api`. Деньги — целые копейки. Запросы передают
`X-Guest-Id`, после входа — `Authorization: Bearer <token>`.
Ошибки: `{ code, message, fields? }`, с корректным HTTP-статусом.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/products?q=&category=&sort=` | Товары, `sort=price-asc` или `price-desc` |
| GET | `/products/:id` | Товар |
| POST | `/auth/register` | `{ name, email, password }` |
| POST | `/auth/login` | `{ email, password }` |
| GET | `/auth/me` | Текущий пользователь |
| POST | `/auth/logout` | Завершить сессию |
| GET | `/cart` | Корзина и итоги |
| POST | `/cart/items` | Добавить `{ productId, quantity }` |
| PATCH | `/cart/items/:id` | Установить `{ quantity }` |
| DELETE | `/cart/items/:id` | Удалить товар |
| POST | `/orders` | `{ delivery, expectedTotal }` + заголовок `Idempotency-Key` |
| GET | `/orders/:id` | Сохранённый заказ владельца |

Auth-ответ: `{ user, token, cart, warnings }`. Корзина:
`{ items: [{ product, quantity }], count, total }`. Вход переносит гостевую
корзину один раз. Остатки проверяются и уменьшаются при создании заказа;
цены/состав сохраняются в заказе как снимок. Повтор запроса с тем же ключом
для того же пользователя возвращает уже созданный заказ.

## Воспроизводимые ошибки и сброс

Для практики доступны служебные mock-endpoints. Их нет в интерфейсе покупателя.
Выполните в консоли браузера на странице магазина:

```js
await fetch('/api/__mock/scenario', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ scenario: 'order-error' }),
});
```

Сценарии применяются однократно к следующему валидному созданию заказа:

- `order-error`: ответ 503, корзина и форма сохраняются, повтор успешен.
- `stock-change`: остаток первого товара уменьшается; ответ 409 и обновлённая
  корзина требуют проверить состав перед повтором. Если товар был один,
  корзина станет пустой; черновик формы останется.
- `session-expired`: ответ 401, повторный вход с сохранённой корзиной и формой.
- `normal`: отмена выбранного сценария.

Полный сброс учебных данных:

```js
await fetch('/api/__mock/reset', { method: 'POST' });
location.assign('/catalog');
```

Сброс возвращает исходные товары и демо-аккаунт, удаляет созданные аккаунты,
заказы, корзины, сессии и черновики текущей вкладки. Другие вкладки после сброса
нужно обновить. MSW перехватывает запросы внутри страницы: эти endpoints
не являются отдельным сервером и не доступны через curl.

По умолчанию задержка 250 мс. В `.env.local` можно установить
`VITE_MOCK_DELAY=1500`, чтобы тренироваться на состояниях загрузки.

## Подключение настоящего бэка

Скопируйте `.env.example` в `.env.local`, установите:

```dotenv
VITE_API_MOCKING=false
VITE_API_BASE_URL=http://127.0.0.1:8080/api
```

Перезапустите Vite (для сборки — пересоберите проект). Бэк уже реализует этот
контракт; инструкция запуска и проверки — в [back/README.md](../back/README.md).
Для настроенного CORS открывайте фронт через `http://127.0.0.1:5173`.
Mock-сессии не подходят для бэка: потребуется новый вход.
Для раздачи production-сборки настройте SPA fallback на `index.html`, чтобы
прямые переходы на `/checkout` и `/products/:id` работали.

Для возврата к автономной имитации задайте `VITE_API_MOCKING=true` и
`VITE_API_BASE_URL=/api`, затем перезапустите Vite. Служебные mock-endpoints
работают только в этом режиме. Данные двух режимов независимы.
